# Themes (Standard and DOS) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Theme setting (Standard, default; DOS) where DOS restyles the library window as an early-1990s DOS graphical shell, with every library action unchanged.

**Architecture:** `AppTheme` lives in `Preferences`. Library-wide behavior (dialogs, sheets, drop, import picker, fixes, removal requests, context menu) moves out of `LibraryView` into a shared modifier, so the existing split-view layout and a new `RetroLibraryView` sit side by side under one switch. Retro building blocks (palette, font, bevel, button style, panel, pixel icon) live in `App/Theme/`.

**Tech Stack:** Swift 6, SwiftUI + AppKit (macOS), Swift Testing (`import Testing`), XcodeGen (`make generate`), CoreText font registration.

**Spec:** `docs/superpowers/specs/2026-10-28-themes-design.md` (read it first; this plan argues from it).

## Global Constraints

- Standard is the default and must look and behave exactly as today. Task 2 is a pure refactor: no visible change, existing tests pass unchanged.
- DOS restyles the library window only. Settings window, import sheets, alerts, confirmation dialogs, file pickers, menus and title bar stay native.
- Theme stored under `UserDefaults` key `appTheme`; missing or unknown values read as `.standard`.
- Theme switching is live (no restart) and keeps selection, filter, search, sort, grid/list mode and inspector visibility.
- DOS palette is fixed in light and dark mode. Values: desktop `#0000AA`, panel `#C0C0C0`, bevel light `#FFFFFF`, bevel dark `#808080`, shadow `#000000`, highlight `#0000AA` with white text, green `#00AA00`, red `#AA0000`, yellow `#FFFF55`, cyan `#55FFFF`.
- Font: PxPlus IBM VGA 8x16 (int10h, CC BY-SA 4.0), bundled unmodified at `App/Resources/Fonts/PxPlus_IBM_VGA_8x16.ttf`; used only at integer multiples of 16 pt; fall back to system monospaced if registration fails.
- Icons are SF Symbols rendered small and scaled up with `.interpolation(.none)`; no new image assets.
- Gate: `make generate test` exits 0; `grep -c warning: build/test.log build/swift-test.log` both 0; `git diff --check origin/main...HEAD` clean.
- Wrap every `make test` / `xcodebuild` run in the shared lock: `until mkdir /tmp/DOSCrateForMac-tests.lock 2>/dev/null; do sleep 15; done; trap 'rmdir /tmp/DOSCrateForMac-tests.lock' EXIT; <command>`.
- Iterate with `xcodebuild ... test -only-testing:DOSCrateTests/<Suite>`; run the full `make generate test` once at the end of each task.

## Review Focus

1. **Theme switch while a sheet is up** (single ImportSheet, BatchImportSheet, Choose Program): the sheet must stay presented, not dismiss or reopen. Owned by Task 2: sheets, dialogs, `.dropDestination` and `.fileImporter` attach *above* the layout switch; the Task 2 test asserts `LibraryLayout` is the only thing that varies with the theme.
2. **Theme switch with an unsaved inspector edit**: `GameDetailView` and `AdvancedTab` flush in `onDisappear`; switching layouts recreates them, so the edit must save. Task 5 adds a test that a pending write registered for a game runs when `RetroLibraryView` replaces the standard layout (or, if not testable headless, a manual checklist step plus a code comment at the switch).
3. **Font missing or fails to register** (e.g. a stripped bundle): DOS still renders with system monospaced. Task 3 tests the fallback path with a bad URL.
4. **Large libraries and long titles**: hundreds of games, titles longer than two lines, missing covers. Grid stays lazy, titles truncate at two lines, `CoverView` placeholder is used. Task 5 smoke test hosts 300 sample records in both modes.
5. **Keyboard in DOS**: Delete removes the selection with the same dialog; ⌘A selects all visible games; ⌘/⇧-click work. Task 2 extracts the selection logic into `GridSelection` with tests; Task 5 wires `.onDeleteCommand` and select-all on both retro modes.
